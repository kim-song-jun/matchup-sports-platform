대회 경기 결과를 **정정**할 때 이미 남아 있던 선수 기록(어시스트·파울)과 결선 승부차기 점수가 사라지던 문제를 고칩니다.

- 정정/재제출 폼이 `assists`/`fouls` 를 읽고 실어 보냅니다. 로컬 타입이 서버 `GameResultParticipantDto` 를 "field-for-field 미러"라고 주장하면서 두 필드를 빠뜨리고 있었고, 서버가 미전달 필드를 `?? 0` 으로 채우기 때문에 **점수만 고치는 정정 한 번에 선수 개개인의 어시스트·파울이 전부 0** 이 됐습니다. 확정 후 그 값을 고칠 유일한 통로가 이 정정 경로라 복구 수단도 없었습니다. 폼에 어시스트·파울 입력란도 추가했습니다.
- 정정 폼이 결선 경기의 승부차기 점수를 **서버가 받아 주는 상태에서만** 이어서 보냅니다(결선 픽스처 + 정규시간 무승부 — 서버 `GamesService.applyPenalties` 판정과 1:1). 예전에는 `penalties` 키가 클라이언트 타입에 아예 없어서 조용히 탈락했고, 결선 무승부 경기의 승자가 정정 한 번에 사라졌습니다.
- 승부차기를 이어 보낼 수 없는 상태(정규시간 승패가 갈림 / 결선 아님 / 기존 기록이 동점·비정수)는 저장 버튼을 누르기 전에 폼이 알립니다. 폼에 승부차기 입력란이 없어 값을 직접 고칠 수단이 없으므로, 값이 사라진다는 사실을 확정 직전에 드러냅니다. 점수 diff 도 승부차기까지 함께 보여줍니다.
- 승부차기 가드 3종(`TOURNAMENT_PENALTY_REQUIRED`/`NOT_ALLOWED`/`INVALID`)의 안내 문구를 한국어 해요체로 매핑합니다. 서버 문구 5개 중 4개가 영문이고 서버에서 바꿀 수 없어, 매핑이 없으면 영문 원문이 그대로 운영자 화면에 노출됩니다.
- 숫자 입력을 정수로 잘라 보냅니다(`@IsInt()` 필드에 소수를 보내 `400 VALIDATION_ERROR` 검증 원문이 노출되는 것을 막습니다). 참가자 기록 입력 5칸을 공용 헬퍼로 통합하면서 터치 타겟을 44px 로 맞추고 `<label htmlFor>`+`<input id>` 연결을 통일했습니다. 경고 라이브 영역(`role="status"`)은 문구가 생기기 전에도 DOM 에 유지해 스크린리더가 내용 변경을 읽도록 했습니다.

**patch 근거**: `apps/v1_web` 프론트엔드 전용 변경이고 서버 코드·Prisma 스키마·API 계약은 한 줄도 바뀌지 않습니다(`apps/v1_api` 는 읽기만 했습니다 — `penalties`/`assists`/`fouls` 는 서버 DTO 에 이미 존재하는 필드입니다). 새 기능이 아니라 **기존 정정 경로가 잃어버리던 데이터를 잃지 않게 하는 결함 수정**이며, 정상 경로(승부차기 없는 일반 경기 정정)의 제출 payload 는 이전과 동일합니다. `v1_api` 는 `fixed` 그룹 정책상 함께 버전이 올라갑니다.
