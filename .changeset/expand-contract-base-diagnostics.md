배포 전 검사(마이그레이션 게이트)가 실패했을 때 **왜 실패했는지**를 알려주도록 고쳤어요.

지금까지는 검사가 죽어도 로그에 `Command failed: git merge-base …` 한 줄만 남아서, 무엇이 잘못됐는지 밖에서 추측해야 했습니다. 실제로 이 상태로 PR 하나가 막혔을 때 원인 가설이 여러 개 나왔고 전부 틀렸어요.

이제 검사가 상황을 이름으로 말합니다. "두 커밋의 공통 조상을 찾지 못했다"처럼 실제로 일어난 일을 적고, git 이 알려준 종료 코드도 함께 남겨요. 저장소가 고장난 경우와 단순히 갈래가 갈린 경우도 구분합니다 — 예전에는 이 둘이 같은 값으로 뭉개져서, 저장소에 문제가 있어도 조용히 넘어간 뒤 엉뚱한 곳에서 죽었습니다.

검사가 base 를 못 찾을 때 다시 받아오는 보완 장치도 되살렸어요. 조건이 "형식이 40자 16진수인가"였는데 그 값은 **항상** 형식이 맞아서, 그 보완 코드는 실제로 한 번도 실행된 적이 없었습니다. 이제 형식 대신 필요한 작업이 실제로 되는지를 확인합니다.

다만 이걸로 모든 경우가 낫는 건 아니에요. base 를 아직 안 받아온 경우는 다시 받아오면 풀리지만, 저장소가 분기점까지 갖고 있지 않은 경우는 평범한 다시받기로 회복되지 않습니다. 그때는 검사가 그 사실을 로그에 그대로 남기니, 다음번엔 추측 없이 원인을 볼 수 있어요.
