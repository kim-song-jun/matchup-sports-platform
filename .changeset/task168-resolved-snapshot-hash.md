Task 168 StageB가 호스트에서 마이그레이션 직전에 `resolved migration-attempt audit snapshot changed`로
멈추던 문제를 고쳤어요.

매니페스트에는 "롤백된 마이그레이션 시도"의 스냅샷 해시가 박제되고, 러너가 실행 시점에 같은 걸 다시 계산해
어긋나면 거부해요. 그런데 두 쪽의 **해시 방법이 달랐어요** — 러너는 결과를 변수에 담아(`$(...)`가 끝의 개행을
버려요) 해시하고, 이전 릴리스 조회 스크립트는 psql 출력을 그대로 파이프해(psql이 붙이는 **끝 개행이 포함돼요**)
해시했어요. 같은 데이터인데 값이 달라지니 디스패치가 매번 거부됐어요.

조회 스크립트도 러너와 같은 방식으로 해시하게 맞췄어요. 실측으로 DB 쪽 데이터는 전혀 바뀌지 않았고(롤백 4건은
7~8월 것 그대로), 순전히 계산 방식 차이였어요. 계약 테스트에 "조회 스크립트의 해시 = 러너 공식" 단언을 넣었고,
파이프 방식으로 되돌리면 그 단언이 red가 되는 것을 확인했어요.
