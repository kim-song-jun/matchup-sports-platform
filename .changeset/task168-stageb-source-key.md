Task 168 StageB가 호스트에서 소스를 스테이징하다가 "Stored source … has a different .source-sha256"로
멈추던 문제를 고쳤어요.

릴리스 소스 트리는 `~/.teameet-alpha-sources/<sha>`에 커밋 SHA 이름으로 놓였어요. 그런데 StageB는
**push 배포가 이미 스테이징하고 라이브로 올린 바로 그 SHA**에 디스패치되고, 최종 스키마와 M11이 들어간
**다른 트리**를 패키징해요. 두 트리가 같은 디렉터리를 두고 다퉈서 StageB는 매번 거부됐고, 거부되지
않았다면 오히려 지금 떠 있는 라이브 트리를 덮어썼을 거예요.

이제 소스 디렉터리 이름은 매니페스트의 소스 키에서 나와요 — 일반 릴리스는 `<sha>`, StageB는
`task168-stage-b-<sha>`. StageB 래퍼만 바꾸지 않고 **복구·롤백·정리(prune)도 같은 규칙**을 쓰게 했어요.
그렇지 않으면 StageB 이후 첫 배포가 실패했을 때 복구가 M11 이전 트리를 다시 라이브로 올리게 돼요.

같이 막은 것: 키가 비어 있으면 `activate`가 소스 루트 자체를 라이브로 가리키고, `prune`이 라이브 트리까지
전부 지울 수 있었어요. 두 함수 모두 빈 키를 거부하고, `deploy-alpha.sh`는 키를 먼저 변수로 읽어 조회에
실패하면 정리를 건너뛰어요.
