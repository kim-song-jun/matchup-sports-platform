# 랜딩 리듬

## 개요

사용자는 읽지 않고 훑는다. 그래서 랜딩·소개 화면은 **큰 타이틀 하나 + 같은 모양의 섹션 반복 + 과감한 여백**으로 짓는다. 변주는 그래픽이 맡고, 레이아웃은 끝까지 한 규칙을 지킨다.
`DESIGN.md` 가 이 스킬보다 우선한다(특히 9절 레이아웃 레시피, 14절 CTA 배치). 충돌하면 DESIGN.md 를 따르고 이 문서를 고친다.

## 다섯 가지 기준

1. **타이틀은 투박해도 크게.** 첫 화면에서 서비스가 뭔지 한 문장으로 읽혀야 한다. 390 폭에서 2줄 이내, 줄당 12자 안팎, `--font-size-heading`(24px) 이상·weight 700. 얇은 웨이트·장식 폰트·소문자 영문 타이틀은 타이틀을 안 넣은 것과 같다.
2. **섹션은 공통 모듈을 반복한다.** 순서는 `키워드 → 타이틀 → 본문 → 그래픽`. 모든 섹션이 같은 순서·같은 간격이다. 섹션 하나에 추가 정보가 생기면 모듈을 깨지 말고 **그 섹션 맨 아래**에 붙인다. 상세는 `references/section-module.md`.
3. **그래픽은 메시지를 그린다.** 오브젝트 선택·생성은 `agy-3d-graphic` 스킬로 한다. 이 스킬은 그래픽이 들어갈 **영역과 크기**만 정한다.
4. **여백이 디자인이다.** 섹션 사이 여백은 `--spacing-12`(48px) 이상, 모듈 안 요소 간격은 12/16/24 세 값만 쓴다. 스크롤 길이를 줄이려고 여백을 좁히지 않는다.
5. **일관성이 있어야 강조가 생긴다.** 배경은 전부 `--bg` 로 두고, 강조할 **한 섹션만** `--grey50` 또는 `--tint-blue` 를 깐다. 두 섹션 이상 색을 깔면 강조가 사라진다. DESIGN.md 15절의 "여백·배경색·구분선 중 하나만" 규칙과 같은 원리다.

## 절차

1. 화면의 **한 문장 약속**을 쓴다(히어로 타이틀 초안). 12자 × 2줄 안에 안 들어가면 약속이 두 개다 — 하나로 줄인다.
2. 섹션 목록을 만들고 각 섹션에 `키워드(2~6자) / 타이틀(≤2줄) / 본문(≤2문장) / 그래픽 메시지` 네 칸을 채운다. 빈 칸이 있는 섹션은 아직 섹션이 아니다.
3. 강조 섹션 하나를 고른다. 나머지는 흰 배경이다.
4. CTA 는 DESIGN.md 14절대로: 주요 CTA 화면당 1개, 보조 1개. **바텀 고정 CTA 금지**(결제·확인 예외만). 랜딩 끝은 CTA 배너 섹션으로 닫는다.
5. UI 착수 규칙(CLAUDE.md): 코드 전에 A·B·C 3안 + 추천안을 내고 선택을 받는다. 3안은 "정보 밀도 / 행동 유도 / 기존 패턴 재사용"처럼 축이 달라야 한다.
6. 구현 후 alpha 배포에서 390 / 768 / 1440 캡처로 정렬·간격·여백을 computed 값으로 확인한다. 로컬 next 서버는 띄우지 않는다.

## 카피 규칙

- 해요체. 타이틀은 명사형 또는 "~해요"로 끝낸다. 느낌표 금지.
- 키워드는 카테고리 라벨(예: `팀 매칭`, `대회 운영`)이지 문장이 아니다.
- 본문은 2문장 이내, 숫자는 한 문장에 하나.
- 빈 상태 카피도 같은 모듈이다: 키워드는 생략, `타이틀(무슨 상태) → 본문(다음 행동) → 그래픽(메시지)`.

## 흔한 실수

| 실수 | 왜 문제인가 | 고치는 법 |
|---|---|---|
| 섹션마다 레이아웃을 다르게 | 사용자가 매 섹션 읽는 법을 다시 배운다 | 모듈 순서 고정, 변주는 그래픽만 |
| 배경색을 번갈아 깖 | 강조할 곳이 없어진다 | 한 섹션만 색, 나머지 `--bg` |
| 타이틀을 작고 얇게 "예쁘게" | 서비스가 뭔지 못 읽는다 | 24px+ · 700 · 2줄 이내 |
| 스크롤이 길어질까 봐 여백 축소 | 덩어리로 못 읽고 혼란 | 48px 이상 유지, 길어도 된다 |
| 추가 정보를 모듈 중간에 끼움 | 리듬이 깨진다 | 섹션 맨 아래에 붙인다 |
| 앱 셸 안 유틸리티 페이지에 히어로 | DESIGN.md 9절 위반 | 이 스킬 대상 아님 |

## 배경
