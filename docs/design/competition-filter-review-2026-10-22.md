## 1. 핵심 판단

현재 필터에는 종목과 성별, 일부 진행 상태가 있지만, 참가할 곳을 찾는 데 가장 중요한 **지금 신청을 받는 곳**을 고르는 기능이 없다.

필터를 구성할 때 다음 세 가지를 구분해야 한다.

1. **유형**: 정규 대회인가, 정규 리그인가.
2. **진행 상태**: 시작 전인가, 진행 중인가, 종료됐는가.
3. **모집 상태**: 지금 신규 참가 신청을 받는가.

특히 리그는 진행 중에도 모집할 수 있다. 따라서 ‘모집 중 → 진행 중 → 종료’라는 하나의 선택 목록으로 만들면 실제 가능한 조합을 표현하지 못한다.

추천 방향은 **유형 탭 유지 + 진행·모집 상태 분리 + 신청 접수 중 퀵 필터**다. 아래 내용은 승인 전 제안이다.

## 2. 현재 구조와 필터

### 2.1 대회와 리그의 구분

| 개념 | 저장값 | 의미 |
|---|---|---|
| 정규 대회 | `kind=regular_tournament` | 단발 대회. 과거 행의 `kind=null`도 현재 조회에서는 대회로 처리 |
| 정규 리그 | `kind=regular_league` | 시즌·시리즈·티어가 연결될 수 있는 리그 |
| 리그 방식 대회 | 대회 종류 + `format=league` | 정규 대회에서 사용하는 경기 진행 방식 |

**리그 방식 대회는 리그 탭으로 보내면 안 된다.** 유형은 `kind`, 경기 방식은 `format`으로 판정한다.

현재 `/league-matches` 목록은 `/tournaments?kind=league`로 이동한다. 목록은 통합됐지만 리그의 일부 하위 상세 경로는 유지된다.

### 2.2 현재 선택할 수 있는 필터

| 항목 | 현재 선택지 | 한계 |
|---|---|---|
| 유형 | 전체 / 대회 / 리그 | 유형 전환 링크가 기존 필터를 유지하지 않음 |
| 상태: 대회 | 전체 / 진행 중 / 종료 | 공개된 모집 중·모집 마감 대회를 따로 찾을 수 없음 |
| 상태: 전체·리그 | 전체 / 진행 중 / 준비 중 / 종료 | 준비 중은 `draft`만 조회하므로 리그의 준비 단계 해석과 범위가 다름 |
| 종목 | 마스터 종목 목록 | 목록 필터와 서버 계약은 존재 |
| 성별 | 전체 / 혼성 / 남성부 / 여성부 | 리그는 현재 성별을 채우는 경로가 없어 실효성이 부족 |

목록 API는 `open`, `closed`도 상태 입력으로 받지만, 현재 화면은 노출된 선택지만 요청으로 통과시킨다. URL에 `status=open`을 직접 넣는 것으로 사용자용 모집 필터가 완성되지는 않는다.

## 3. 대회에서 가능한 상태

### 3.1 정규 대회에서 쓰는 상태 6종 (공유 enum은 리그 보류까지 7종)

| 저장 상태 | 의미 | 일반 공개 목록 | 신규 신청 |
|---|---|---|---|
| `draft` | 운영자 작성·준비 단계 | 제외 | 불가 |
| `open` | 운영자가 모집을 열어둠 | 포함 | 마감·정원 등 추가 조건 충족 시 가능 |
| `closed` | 운영자가 모집을 닫음 | 포함 | 불가 |
| `in_progress` | 대회 진행 중 | 포함 | 불가 |
| `completed` | 대회 종료 | 포함 | 불가 |
| `cancelled` | 대회 취소 | 제외 | 불가 |

공개 목록의 ‘전체’는 위 6개 전체가 아니다. 공개 허용 상태만 뜻한다. 취소나 비공개 초안이 필터를 통해 공개돼서는 안 된다.

### 3.2 모집 상태를 추가 계산해야 하는 이유

대회의 신청 접수 조건은 다음과 같다.

- 상태가 `open`이어야 한다.
- 신청 마감이 있으면 현재 시각이 마감 시각을 지나지 않아야 한다.
- 정원에 여유가 있어야 한다.
- 개별 팀의 종목·권한·기존 신청 등 추가 신청 조건을 충족해야 한다.

대회는 신청 마감이 없어도 `open`이면 다른 조건에 따라 모집할 수 있다. 이는 마감 미설정 시 모집하지 않는 리그와 다르다.

| 실제 상황 | 사용자에게 필요한 표현 | 필터 해석 |
|---|---|---|
| 모집 열림 + 마감 전 + 자리 있음 | 신청 접수 중 | 신청 접수 중에 포함 |
| 모집 열림 + 마감 미설정 + 자리 있음 | 신청 접수 중 | 신청 접수 중에 포함, 마감 임박에는 제외 |
| 모집 열림 + 기한 경과 | 신청 기간 마감 | 모집 종료에 포함 |
| 모집 열림 + 정원 점유 완료 | 정원 마감 | 모집 종료에 포함 |
| 모집 열림 + 예약률 80% 이상 + 자리 있음 | 잔여 자리 적음 | 신청 접수 중에 포함 |
| 운영자가 모집 종료 | 모집 종료 | 모집 종료에 포함 |
| 진행 중 | 진행 중 · 신청 종료 | 진행 상태와 모집 상태를 각각 표시 |
| 종료 | 종료 · 신청 종료 | 진행 상태와 모집 상태를 각각 표시 |

‘마감 임박’은 시간, ‘잔여 자리 적음’은 정원이다. 두 조건을 같은 이름으로 묶지 않는 편이 명확하다. 현재 카드의 ‘거의 마감’은 정원 예약률 80% 이상을 기준으로 하며, 시간 기준이 아니다.

### 3.3 정원 계산

현재 신청 서비스에서 정원을 점유하는 신청 상태는 다음 4개다.

- `awaiting_payment`: 결제 대기
- `payment_checking`: 입금 확인 중
- `paid`: 결제 완료
- `confirmed`: 참가 확정

따라서 **참가 확정 팀 수가 정원보다 적다고 해서 바로 신청 가능인 것은 아니다.** 결제 대기 등이 자리를 점유하고 있을 수 있다.

잔여 자리 필터를 만들면 서버의 동일한 정원 판정을 사용해야 한다. 목록 카드의 숫자만 브라우저에서 계산해 현재 페이지를 거르는 방식은 전체 목록 필터가 아니다.

## 4. 리그에서 가능한 상태

### 4.1 진행 상태 3종과 저장 상태의 관계

| 리그의 진행 상태 | 대응하는 저장 상태 | 해석 |
|---|---|---|
| 준비 중 | `draft`, `open`, `closed` | 리그 응답의 `state=draft`에 대응 |
| 진행 중 | `in_progress` | 리그 응답의 `state=active`에 대응 |
| 종료 | `completed` | 리그 응답의 `state=completed`에 대응 |
| 취소 | `cancelled` | 공개 목록 제외 |
| 보류 | `on_hold` | 관리자만 재개할 수 있는 상태. 공개 목록·경기는 숨김 |

현재 통합 목록의 준비 중 필터는 `status=draft` 하나만 요청한다. 리그에서 ‘준비 중’을 진행 단계로 정의할 경우에는 위 3개 상태를 일관되게 포함해야 한다.

또한 현재 대진 생성 경로가 리그 저장 상태를 `in_progress`로 옮기므로, 이 값만으로 **실제 첫 경기가 시작됐다**고 단정할 수 없다. ‘진행 중’을 운영 단계로 쓸지 실제 경기 시작 기준으로 쓸지는 별도 확정이 필요하다.

### 4.2 리그의 모집 판정

리그는 다음 조건으로 신청 접수 여부를 판정한다.

- 종료·취소·보류된 리그가 아니며 공개 설정이어야 한다.
- 신청 마감이 설정돼 있어야 한다.
- 마감 시각을 지나지 않아야 한다.
- 선택적 참가팀 정원(`maxTeams`)이 있으면 예약 자리가 남아 있어야 한다.

대회와 달리 `status=open`을 요구하지 않는다. 대진 생성도 신청 창을 닫는 기준이 아니다. 마감 시각과 정확히 같은 순간은 현재 계약상 접수 허용이며, 그 이후에 닫힌다.

| 진행 상태 | 마감 설정 | 신규 신청 | 사용자 표현 예시 |
|---|---|---|---|
| 준비 중 | 미래 또는 현재 시각 | 가능 | 준비 중 · 신청 접수 중 |
| 준비 중 | 과거 | 불가 | 준비 중 · 신청 마감 |
| 준비 중 | 미설정 | 불가 | 준비 중 · 접수 안 함 |
| 진행 중 | 미래 또는 현재 시각 | 가능 | 진행 중 · 신청 접수 중 |
| 진행 중 | 과거 | 불가 | 진행 중 · 신청 마감 |
| 진행 중 | 미설정 | 불가 | 진행 중 · 접수 안 함 |
| 종료 | 어떤 값이든 | 불가 | 종료 |
| 취소 | 어떤 값이든 | 불가 | 공개 목록 제외 |

미설정은 ‘곧 모집 예정’이라는 뜻이 아니다. 모집 시작 시각이나 예약 모집 계약이 없으므로, 임의로 ‘모집 예정’이라고 표시하면 안 된다.

### 4.3 리그에 그대로 적용하면 안 되는 필터

- **잔여 정원**: 리그에는 선택적 `maxTeams`가 있다. null은 무제한이며, 설정되면 신청 접수 판정에 반영한다. 과거 기본 `teamCount`를 리그 정원으로 해석하면 안 된다. 별도 잔여 정원 필터는 이번 화면 구성에 추가하지 않는다.
- **성별 부문**: 현재 리그 생성·저장 경로에서 값을 채우지 않는다. 기능을 갖추기 전에는 리그 탭에서 숨기는 편이 적절하다.
- **티어 숫자 표시**: 시리즈마다 디비전 명칭이 다를 수 있다. 숫자만 보고 일괄적으로 ‘1부’라고 만들어 표시하면 안 된다.

## 5. 추천 필터 상세

### 5.1 기본 구성

| 필터 | 대회 | 리그 | 역할 |
|---|---|---|---|
| 유형 | 대회 | 리그 | 목록의 종류 선택 |
| 신청 접수 중만 | 사용 | 사용 | 빠르게 참가할 곳 찾기 |
| 진행 상태 | 전체 / 시작 전 / 진행 중 / 종료 | 전체 / 준비 중 / 진행 중 / 종료 | 관람·일정·결과 탐색 |
| 모집 상태 | 전체 / 신청 접수 중 / 모집 종료 | 전체 / 신청 접수 중 / 접수 안 함 | 신청 창의 상태 구분 |
| 종목 | 실제 지원 종목 | 실제 지원 종목 | 팀 종목에 맞는 목록 탐색 |
| 성별 부문 | 전체 / 남성부 / 여성부 / 혼성 / 미지정 | 현 단계 숨김 제안 | 참가 부문 탐색 |
| 기간 | 개최 기간 | 시즌 기간 | 가능한 일정의 대회·시즌 탐색 |

대회 ‘시작 전’은 공개된 `open`, `closed`를 묶는 제안이다. 실제 시작 시각 경과만으로 상태를 자동 변경하는 의미는 아니다.

성별 `null`은 값이 미지정된 상태다. 확인 없이 혼성과 합치거나 ‘누구나 참가 가능’으로 해석하지 않는다. 현재 카드의 ‘성별 구분 없음’ 표현과도 의미를 정리할 필요가 있다.

### 5.2 신청 접수 중 퀵 필터

목록에서 가장 자주 쓰는 조건으로 노출하는 것을 추천한다. 상세 필터의 모집 상태와 같은 값을 제어해야 한다.

예를 들어 퀵 필터를 켜면 상세 필터도 ‘신청 접수 중’으로 선택되고, 상세 필터를 다른 값으로 바꾸면 퀵 필터도 꺼져야 한다. 서로 다른 필터 두 개로 구현하면 화면과 조회 결과가 어긋난다.

‘신청 접수 중’은 모집 창과 정원 조건을 뜻한다. 로그인·팀 권한·종목 일치·중복 신청 등 개인별 조건 통과를 보장하지 않는다. 개인별 자격까지 계산하지 않는 동안에는 ‘내 팀 신청 가능’이라는 이름을 쓰지 않는다.

### 5.3 날짜 필터

기간은 시작일 하나만 비교하기보다 **선택 기간과 개최·시즌 기간이 겹치는 항목**을 찾는 방식이 적절하다.

예: 11월을 선택했다면 10월에 시작해 12월에 끝나는 리그도 포함한다. 시작일이 11월인 리그만 포함하면 참여·관람 목적과 어긋날 수 있다.

날짜 미정 항목은 별도 표시하고, 날짜 필터를 선택했을 때 포함할지 정책을 정해야 한다. 제안은 날짜 범위를 지정하면 날짜 미정은 제외하고, 기본 전체에서는 유지하는 것이다. 날짜 경계는 한국 시간 기준으로 통일한다.

### 5.4 추가 상세 필터

| 필터 | 추천 범위 | 선행 조건 |
|---|---|---|
| 진행 방식 | 대회: 토너먼트 / 조별+결선 / 리그 방식 | `format` 목록 필터 API 추가 |
| 참가비 | 대회 우선: 무료 / 금액 범위 | 필터 API와 금액 단위 정의. 리그는 실제 금액 입력·노출 계약 확인 후 적용 |
| 지역 | 공통 | 대회 장소 문자열을 지역 ID로 취급하지 않도록 지역 데이터 정리 |
| 시리즈 | 리그 | 실제 시리즈 목록과 연결 |
| 시즌 | 리그 | 연도와 `seasonNo` 구분. 시즌 번호를 연도로 해석하지 않음 |
| 디비전·티어 | 리그 | 시리즈별 명칭 제공, 선택한 시리즈에 맞는 옵션 표시 |

상금·상품 유무는 현재 자유 입력 문구와 숫자 필드가 함께 있어, ‘상금 있음’을 정확히 정의하기 전에는 우선 필터로 권하지 않는다. 실력 수준도 티어를 사용자 실력으로 바로 치환하지 않는다.

### 5.5 정렬은 필터와 분리

최신 dev의 기존 API 기본값은 진행·모집·종료 단계별 정렬이다. 새 화면은 최신 등록순을 명시해 요청한다. 다음 정렬을 별도로 제공하면 탐색 목적에 더 맞는다.

| 정렬 | 적합한 목적 | 주의점 |
|---|---|---|
| 최신 등록순 | 새 대회·시즌 발견 | 새 화면의 기본 선택 |
| 마감 가까운 순 | 신청할 곳 찾기 | 신청 접수 중 항목 우선 맥락에서 제공. 마감 미설정 항목 처리 명시 |
| 개최 가까운 순 | 다가오는 일정 찾기 | 리그는 시즌 시작 기준인지 다음 경기 기준인지 명시 |

‘인기순’은 조회·신청·참가 수 중 무엇을 뜻하는지 정하기 전에는 추가하지 않는 편이 낫다.

## 6. 조합 규칙과 사용 예시

서로 다른 필터 축은 AND로 결합한다. 같은 축의 복수 선택을 지원한다면 OR로 결합한다. 초기 구성에서는 진행·모집 상태를 각각 단일 선택으로 두어도 충분하다.

| 사용자 목적 | 선택 조합 | 기대 결과 |
|---|---|---|
| 지금 참가할 풋살 대회 찾기 | 대회 + 풋살 + 신청 접수 중 | 마감·정원 조건을 통과한 공개 대회 |
| 모집이 끝났지만 곧 열릴 대회 보기 | 대회 + 시작 전 + 모집 종료 | 공개된 시작 전 대회 중 신청을 받지 않는 항목 |
| 도중에 합류할 리그 찾기 | 리그 + 진행 중 + 신청 접수 중 | 진행 단계이면서 모집 창이 열린 리그 |
| 새 시즌 준비 상황 보기 | 리그 + 준비 중 | 모집 여부와 무관한 준비 단계 리그 |
| 지난 대회 결과 찾기 | 대회 + 종료 | 공개된 종료 대회 |
| 11월에 열리는 일정 찾기 | 기간 11월 | 선택 기간과 개최·시즌 기간이 겹치는 항목 |

‘종료 + 신청 접수 중’은 성립하지 않는다. 새 UI에서는 종료 선택 시 모집 조건을 해제하며 변경 사실을 알려주는 방식 등을 검토할 수 있다. 단, 이미 공유된 URL이 모순 조건을 담으면 조회 범위를 몰래 넓히지 말고 조건 충돌과 해제 방법을 안내하는 것이 안전하다.

‘마감 임박’을 추가한다면 기준을 ‘3일 이내’처럼 명시해야 한다. 이 숫자는 현재 정책이 아니라 확정할 제안값이다.

## 7. 탭 전환·초기화·화면 동작

### 7.1 탭을 바꿀 때

- 종목, 기간, 신청 접수 여부처럼 공통으로 유효한 조건은 유지한다.
- 대회 전용 성별·진행 방식, 리그 전용 시리즈·티어는 다른 유형으로 이동할 때 해제한다.
- 호환되지 않는 조건을 해제했다면 사용자에게 짧게 알린다.
- 대회의 시작 전과 리그의 준비 중은 공통 진행 단계로 매핑하되, 범위를 먼저 확정한다.
- 필터가 바뀌면 페이지 번호와 모바일 누적 결과를 초기화한다.

전체 탭에서 성별이나 진행 방식 같은 대회 전용 필터를 제공한다면, ‘대회에만 적용’이라는 모호한 혼합 조회를 피해야 한다. 해당 조건 선택 시 대회로 범위를 좁히고 이를 표시하거나, 유형을 먼저 선택하도록 안내하는 방식을 확정해야 한다.

### 7.2 필터 적용 방식

현재는 옵션마다 링크로 즉시 URL을 변경한다. 항목이 늘어나면 필터 안에서 여러 조건을 고른 뒤 **결과 보기**로 한 번에 적용하는 방식을 추천한다.

- 시트를 열면 적용된 조건으로 임시 선택값을 채운다.
- 적용하면 URL과 목록을 함께 갱신한다.
- 적용하지 않고 닫으면 임시 변경은 버린다.
- 초기화는 필터만 해제하며 현재 유형 탭은 유지한다.
- 공유 링크·새로고침·뒤로가기로 적용된 조건을 복원한다.
- 실제 조회하지 않은 결과 수를 버튼에 임의로 표시하지 않는다.

### 7.3 빈 결과와 오류

필터 결과가 없을 때와 조회 실패를 구분해야 한다.

| 상황 | 안내 예시 | 후속 행동 |
|---|---|---|
| 조건에 맞는 항목 없음 | 선택한 조건에 맞는 리그가 없어요 | 필터 초기화 |
| 공개 항목 자체가 없음 | 아직 공개된 대회가 없어요 | 다른 유형 보기 |
| API 조회 실패 | 목록을 불러오지 못했어요 | 다시 불러오기 |
| 조건끼리 충돌 | 종료된 리그는 신청을 받지 않아요 | 신청 접수 조건 해제 |

현재는 종료·리그 조회 결과가 비어도 ‘모집 중인 대회가 없어요’라고 안내한다. 선택한 유형과 조건에 맞는 문구로 바꿀 필요가 있다.

## 8. 발견한 현재 구현의 빈틈

| 항목 | 현재 근거 | 사용자 영향 | 개선 방향 |
|---|---|---|---|
| 모집 필터 누락 | 상태 옵션에 open·closed가 없음 | 참가할 곳을 바로 찾기 어려움 | 모집 상태 축 추가 |
| 리그 준비 중 범위 불일치 | 필터는 draft만, 리그 상태 매핑은 draft·open·closed | 준비 중인 일부 리그가 누락될 수 있음 | 공통 진행 단계 정의 |
| 리그 성별 필터 | 입력 경로 없이 공통 필터 노출 | 선택하면 리그가 빠질 수 있음 | 리그에서 숨기거나 데이터 계약 먼저 구축 |
| 탭 전환 초기화 | 유형 링크가 kind만 지정 | 종목 등을 매번 다시 골라야 함 | 공통 조건 유지 |
| 카드와 신청 판정 불일치 가능 | 카드 상태 배지에서 마감 시각 미반영 | 모집 중처럼 보이나 신청은 거절될 수 있음 | 모집 판정 서버 기준 통일 |
| 빈 결과 안내 고정 | ‘모집 중인 대회’ 문구 사용 | 실제 조회 목적을 잘못 설명 | 유형·필터별 안내 |
| 기본 정렬 한 종류 | 최신 dev는 단계별 정렬 | 곧 마감하거나 열리는 항목 찾기 어려움 | 목적별 정렬 추가 |
| 준비·진행 의미 혼동 | 대진 생성이 리그 in_progress로 연결 | 첫 경기 전인데 진행 중으로 읽힐 수 있음 | 운영 단계와 실제 경기 단계 구분 확정 |

위 내용은 코드상 확인한 구조와 그에 따른 위험이다. 현재 배포에서 각 사례가 몇 건 발생하는지는 별도 실측이 필요하다.

## 9. API와 데이터에서 필요한 준비

초기 조사 시점 목록 API의 필터 입력은 `kind`, `status`, `sportId`, `genderCategory`다. 페이지·커서·개수 입력도 받는다. 날짜·모집 가능 여부·지역·경기 방식·금액·시리즈·시즌·티어·사용자 선택 정렬은 현재 이 DTO의 필터 계약에 없다.

향후 구현 시에는 다음 원칙이 필요하다.

1. 모집 판정은 서버에서 계산하고 목록·상세·신청 API가 같은 규칙을 사용한다.
2. 필터는 페이지네이션 전에 적용한다. 현재 받은 20개만 거르면 전체 결과와 총 건수가 틀린다.
3. 공개 상태 범위는 유지한다. 필터 추가를 이유로 초안·취소 항목을 공개하지 않는다.
4. 마감·정원 때문에 접수가 닫혔을 때 이유를 응답으로 구분할 수 있게 한다.
5. 목록의 신청 접수 표시는 보장 예약이 아니다. 실제 신청 시 트랜잭션 안에서 정원과 마감을 재검사한다.
6. 마감 경과·정원 변경 뒤 캐시와 배지가 오래 남지 않도록 갱신 시점을 정한다.
7. API 계약을 바꾸면 프론트 타입·훅·MSW·테스트·`docs/api/`를 함께 맞춘다.

## 10. 내 신청 상태와 경기 상태는 별도 영역

전체 탐색 필터에 모든 상태를 섞으면 선택지가 과도해진다. 아래 상태는 실제로 존재하지만 다른 위치에서 다루는 것이 적절하다.

### 10.1 내 팀의 참가 신청 상태

| 저장값 | 의미 |
|---|---|
| `draft` | 작성 중 |
| `submitted` | 제출됨 |
| `awaiting_payment` | 결제 대기 |
| `payment_checking` | 입금 확인 중 |
| `paid` | 결제 완료 |
| `confirmed` | 참가 확정 |
| `waitlisted` | 대기 등록 |
| `cancel_requested` | 취소 요청 중 |
| `cancelled` | 취소됨 |

이 표는 저장 가능한 상태 목록이며, 모든 종류에서 동일한 순서로 전이한다는 뜻은 아니다. ‘내 신청’이나 ‘내 팀 참가’ 화면에서 필터로 쓰는 편이 적절하다. `waitlisted`가 존재한다고 해서 정원 마감 대회에 누구나 신규 대기 신청할 수 있는 것은 아니다. 현재 신규 신청 서비스는 정원이 가득 차면 거절한다.

결제 자체에도 `ready`, `paid`, `failed`, `cancelled`, `refunded`가 있지만, 대회 진행 상태와 분리해 내 신청·결제 이력에서 다뤄야 한다.

### 10.2 개별 경기의 상태

공통 경기 표시 모델은 예정, 결과 대기, 진행 중, 일시 중단, 종료, 취소를 구분한다. 이는 리그·대회 전체의 상태가 아니다.

예를 들어 진행 중인 리그에도 예정 경기와 종료 경기가 함께 존재한다. 개별 경기 상태는 대회 상세의 일정·경기 목록 필터에 배치하는 편이 적절하다. ‘지금 경기 중인 리그’ 탐색을 추가하려면 현재 라이브 경기 유무를 별도 집계해야 한다.

## 11. 적용 순서 제안과 미확정 사항

### 우선순위

1. **핵심**: 신청 접수 중 필터, 진행·모집 상태 분리, 리그 준비 중 범위 통일.
2. **일관성**: 카드·상세·신청 판정 일치, 리그 성별 필터 정리, 탭 전환 조건 유지, 빈 결과 안내 수정.
3. **탐색 확장**: 기간·정렬·대회 진행 방식·참가비.
4. **데이터 준비 후**: 지역·리그 시리즈·시즌·디비전.

### 사용자 결정이 필요한 항목

- 리그 ‘진행 중’을 현재 운영 단계로 유지할지, 실제 첫 경기 시작 기준으로 재정의할지.
- 대회 ‘시작 전’과 리그 ‘준비 중’의 화면 명칭을 통일할지.
- 접수하지 않는 리그의 기본 명칭을 ‘접수 안 함’으로 두고 상세 이유를 표시할지.
- 마감 임박을 추가한다면 시간 기준을 며칠로 둘지.
- 필터 적용을 즉시 반영으로 유지할지, 여러 조건 선택 후 결과 보기로 바꿀지.

이 문서 작성은 위 제안의 승인이나 구현 착수를 의미하지 않는다.
