# 정규대회 하나 · 상위/하위 결선 · 시상

상태: 구현 및 계약 검증 진행 중. 변경 후 alpha QA 대기.

정본: [대회 플로우](../design/competition-canonical-flow.md), [작업 문서](../../.github/tasks/20261057-admin-bracket-canvas.md).

## 운영자 흐름

1. 별도 검증용 정규대회를 만들고 `group_knockout`, 2조×4팀, 1회전, 상·하위 결선을 선택한다. 조별 12경기와 결선 6경기, 총 18경기를 확인한다.
2. 등록된 8개 테스트 팀을 조별 자리에 배정한다. 조별 결과가 미확정인 동안 결선 자동·직접 배정이 거절되는지 확인한다.
3. 조별 결과를 확정하고 순위를 확인한다. 동률은 운영자의 확인 전 임의 배정되지 않아야 한다.
4. 순위대로 채우면 각 조 1·2위는 상위, 3·4위는 하위 첫 결선에 들어가야 한다. 수동 자리·조 편성·경기 수정 경로로 범위를 바꿀 수 없어야 한다.
5. 상위·하위 4강 결과를 각각 확정한다. 승자는 같은 범위 결승으로만 이동해야 한다. 두 결승 결과를 확정한다.
6. 시상 설정에서 상위/하위 팀 상금·부상을 저장하고 새로고침 후 같은 값을 확인한다. 0원 유지, 빈 범위 생략, 전체 목록 비우기를 확인한다.
7. 개인상 각 항목을 전체/상위/하위로 저장하고 재조회한다. 같은 종류를 다른 범위에 등록할 수 있고, 같은 범위 중복은 거절되어야 한다.
8. support 읽기 권한에서 시상 조회는 가능하고 저장 동작은 노출·허용되지 않아야 한다.

## 참가자 흐름

1. 같은 대회 상세의 순위·대진표로 이동한다. 경기 전에도 1·2위→상위, 3·4위→하위 규칙을 알 수 있어야 한다.
2. 진행 중 순위를 최종 진출로 표시하지 않아야 한다. 결과는 확정됐으나 진출 요약이 준비되지 않은 경우, 전체 상위 2팀 진출로 오해시키지 않고 확인 중임을 표시한다.
3. 상위·하위 결선을 각각 구분해서 볼 수 있어야 한다. 경기 상세와 뒤로가기가 같은 대회 맥락을 유지해야 한다.
4. 결과 화면에 두 결승과 각 우승팀이 보여야 한다. 시상 화면에 저장된 팀 시상 안내와 전체/상위/하위 개인상이 구분돼야 한다. 미등록 시상은 임의로 만들어 표시하지 않는다.
5. 390/768/1440px에서 데이터 로딩 후 본문 끝까지 스크롤한다. 텍스트 줄바꿈·대진 구분·마지막 경기/시상·고정 CTA 겹침·터치 영역을 확인한다.
6. 기존 단일 결선 대회의 결과·전체 시상 표시를 비교한다. 1구간은 경기, 2구간은 전반/후반으로 표기돼야 한다.

## 증거와 회수

- 변경 전 alpha 템플릿과 공개 화면을 관찰하며 기존 대회는 수정하지 않는다.
- 변경 후 증거에 실제 배포 SHA, 검증용 대회 ID, 역할, viewport, console/network 결과와 before/after 이미지를 기록한다.
- 검증용 대회만 공개 노출을 정리한다. 기존 경기·등록·결과를 삭제하거나 seed/reset하지 않는다.
- ego 작업 공간은 검증 종료 시 `task.finish({ keep: [] })`로 닫는다. 이번 작업이 시작한 테스트 프로세스만 회수한다.
