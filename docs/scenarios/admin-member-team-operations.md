상태: 구현·로컬 검증 완료, PR 반영 및 원격 검증 진행. Alpha 실측 미실행.

## 범위와 사용자

- 화면 4개: `/admin/users`, `/admin/users/:id`, `/admin/teams`, `/admin/teams/:id`.
- 운영자(owner/ops)는 상태·문의·참가 자료를 확인하고 사유를 남겨 활성 일반 회원의 화면을 조회한다. support는 기존 조회 권한을 유지하고 대리 접속은 시작할 수 없다.
- 회원 대리 조회 중에는 대상 회원의 기존 가입/약관/권한 게이트가 유지된다. 신청·수정·전송·운영 경로·소켓은 차단된다.

## 확인할 흐름

1. 팀 목록에서 종목·상위/하위 지역·팀장 검색을 빠르게 연속 변경하고 상세 왕복 및 이전/다음 페이지에서 조건을 확인한다.
2. 회원/팀 상세에서 상태 변경 사유·처리자·시각, 관련 문의 작성자/신고 대상 구분, 예정 경기와 참가 이력을 조회한다. 목록별 다음 페이지와 API 실패/재시도를 확인한다.
3. 회원의 가입 보완 항목·탈퇴 예정일을 확인한다. 상태만 deleted인 계정은 최종 삭제할 수 있고 deletedAt이 있는 계정은 다시 삭제하지 못한다.
4. 팀장의 회원 상세로 이동하고, 팀 경기·대회·리그 이력이 각각 관리자 shell 안의 올바른 경로로 이어지는지 확인한다. 신뢰 정보의 표본/추정 상태를 구분한다.
5. 최근 로그인한 owner/ops로 활성 일반 회원을 선택하고 5자 이상 사유로 회원 화면 조회를 시작한다. 원래 관리자 로그인 쿠키를 유지하며 새 일반 회원 로그인 쿠키/응답 토큰은 발급되지 않아야 한다.
6. 대리 조회의 상단 표시와 복귀 버튼을 확인하고 대상 회원으로 조회되는지 확인한다. POST/PUT/PATCH/DELETE, 운영 페이지와 인증 발급 및 Socket.IO를 시도하면 거부돼야 한다.
7. 세션 위조·원래 세션 변경·만료·양쪽 epoch 변경·관리자 권한 회수·대상 관리자 승격 후 조회를 거부하고 관리자 신원으로 조용히 대체하지 않아야 한다.
8. 복귀하면 종료 감사 기록을 남기고 marker만 제거하며 원래 관리자 상세로 돌아온다. 캐시/소켓/다른 탭의 신원 자료도 갱신돼야 한다. 종료 감사 저장 실패는 오류로 남기고 성공 이동을 하지 않는다.

## 실행 근거와 한계

- CLI/인프로세스 실제 HTTP: `apps/v1_api/src/admin/member-access.controller.spec.ts`에서 실제 전역 guard·인증 guard·컨트롤러·서비스를 거쳐 발급/조회/쓰기 차단/운영 경로 차단/종료/재사용/위조/만료/권한 변경을 확인한다. Prisma 저장소는 이 단위 경계에서 격리 대역이다.
- PostgreSQL: `apps/v1_api/test/admin-member-access.integration-spec.ts` 3개 시나리오로 실제 잠금 SQL·감사 저장·종료 JSON 조회·epoch 변경·대상 이력 분리를 검증하도록 등록했다. 로컬 DB가 없어 실행은 원격 CI에서 확인한다. 통합 runner는 승인된 폐기 가능 DB의 파일별 clone만 허용한다.
- UI/HTTP 계약: 신규 운영 정보/대리 조회 진입·만료·종료 실패, 삭제 구분, 목록 조건 왕복, 팀장 링크, 기존 로그인/소켓/공유 상세 값을 단위 테스트로 검증한다. 브라우저 레이아웃 합격 근거로 사용하지 않는다.
- Alpha 브라우저/뷰포트: 0/4 화면, 0/3 폭(390/768/1440). 현재 세션에 ego-lite 도구/스킬이 없어 실제 로그인·클릭·전후 screenshot·console/network를 실행하지 않았다. 다른 browser-use나 로컬 next로 대체하지 않았다. 미배포이며 성공 판정으로 표시하지 않는다.
- 새 DB schema/migration, 운영 데이터 변경, dev/main 머지는 없다. 테스트 서버는 테스트 종료 때 닫고, 작업 worktree는 미병합 변경을 보존한다.
