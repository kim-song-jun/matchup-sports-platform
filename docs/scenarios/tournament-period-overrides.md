# 단계·조·경기별 경기 시간

Status: 관련 5개 파일 고유187개 회귀·Web 타입 검사 PASS, 변경 후 alpha 미검증

## 계약과 수정 이유

[정본 §4·§6](../design/competition-canonical-flow.md), [피리어드 API](../api/domains/tournaments.md)를 따른다. 조별과 결승 시간을 나누기 위해 운영 중 전체 시간을 바꾸던 우회를 없앤다.
우선순위는 경기 > 조 > 단계 > 기본값이다. 이미 시작한 경기는 보존하고, 시작 전 경기에서 해당 상위 설정을 따르는 대상만 갱신한다. 조·경기 재정의는 대회 기본값을 바꾸지 않는다.

2026-10-30 리뷰 후속은 두 편집 경계를 보강한다. 취소한 입력은 재진입 때 사라져야 하고, 단계 편집 중 조회가 갱신돼도 편집 시작 버전을 유지해 다른 운영자의 수정을 덮어쓰면 안 된다.

## 수동 alpha 시나리오

페르소나: 쓰기 가능한 플랫폼 관리자. 운영자 간 충돌은 별도 두 세션을 사용한다. 390/768/1440에서 실제 화면·console/network·저장 후 재조회 결과를 기록한다. 현재 실행 0/9, after viewport 0/3이다.

1. 대회 생성에서 기본 전후반 20분, 조별 단판 15분, 결승 전후반 10분을 저장한다. 다시 열어 같은 값과 각 단계 새 경기의 실제 설정을 확인한다.
2. 기본값을 바꾼다. 별도 단계 설정은 유지하고 기본값을 따르는 시작 전 경기만 바뀌어야 한다. 이미 시작·종료된 경기는 유지한다.
3. B조만 전후반 10분, A조 경기 하나만 단판 12분으로 정한다. 조별 단계·대회 기본값을 바꿔도 이 별도 설정은 남아야 한다.
4. 조·경기의 위 설정 따르기로 복귀한다. 바로 위 시간으로 돌아가되 경기별 복귀가 출전 인원·결과 등 시간 외 규칙을 바꾸면 안 된다.
5. 리그 경기 하나만 단판으로 바꾸고 기본값 유지·복귀·시작 후 잠금을 확인한다. 강 단계 조별 변경은 거절하고 단계 설정을 사용한다.
6. 대회 목록 보기의 조·경기 수정창에서 시간만 고치고 취소한다. 같은 대상을 다시 열면 서버 값이어야 하며, 이름·장소만 저장할 때 취소한 시간이 함께 전송되면 안 된다.
7. A경기 편집을 취소한 뒤 B경기를 열고 다시 A경기로 돌아온다. 이전 미저장 입력이 되살아나면 안 된다. 같은 창을 계속 편집하는 동안의 조회 갱신은 입력을 지우면 안 된다.
8. 운영자 A가 결승 시간 편집을 시작한 뒤 B가 같은 결승 시간을 변경한다. A 화면을 다른 창에서 돌아오는 등으로 최신 조회한 후 저장·기본값 사용을 각각 시도한다. 충돌을 알리고 B의 저장값은 유지해야 한다.
9. A가 결승 시간을 편집하는 동안 B가 기본 장소만 바꾼다. A 저장은 단계 값이 그대로인 것을 확인한 뒤 최신 버전으로 한 번 재시도할 수 있어야 한다. 네트워크 실패는 성공으로 표시하지 않고 입력을 유지한다.
