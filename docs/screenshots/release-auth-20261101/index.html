번호·로그인 개선 — 운영 승격 보고서

카톡 결론(같은 번호로 다른 계정 인증은 불가능, 내 번호 다시 인증은 가능)대로 동작하는지, 첫 가입부터 같은 번호인 사람이 들어오는 경우까지 운영(지금)과 alpha(바뀐 뒤)를 같은 상태로 만들어 비교했어요. 두 곳 모두 서버에 쓰지 않고 응답을 브라우저 안에서 가로채 상태를 만들었어요(운영 쓰기 0, alpha 는 로그인 2회 외 쓰기 0). 항목마다 승인 / 수정 요청 / 이번 배포에서 빼기를 고르고 결과를 복사해 주세요.

기 · 무엇이 막혀 있었나

  • 비밀번호 재설정 메일이 한 통도 안 나갔어요 — 10/31 운영 메일 권한을 고쳐 지금은 이미 나가요.
  • 이메일 가입자는 카카오·애플을 붙일 방법이 없었어요. "이메일 인증을 마친 뒤 다시"라는 안내만 있고, 그 인증을 할 화면이 없었어요.
  • 이메일 가입은 마지막 단계에서야 "이미 사용 중인 번호"를 알렸어요.
  • 탈퇴를 신청한 계정은 돌아올 길이 없었고, 그 계정이 쥔 번호는 영원히 묶였어요(30일 뒤 자동 삭제가 실제로는 없었어요).
  • 번호를 새로 받은 사람은 갈 곳이 없었어요.

승 · 원칙(카톡 결론과 같음)

  • 번호 하나 = 계정 하나. 다른 계정은 같은 번호로 인증할 수 없어요.
  • 내 번호는 언제든 다시 인증할 수 있어요.
  • 새 로그인 수단(카카오·애플·이메일)은 원래 계정에 한 번 로그인한 사람에게만 붙어요. 번호만으로 남의 계정에 들어가는 길은 만들지 않아요(번호를 새로 받은 사람이 이전 주인 계정에 들어가는 일을 막아요).
  • 번호를 쥔 계정이 탈퇴 신청 중이면, 철회해서 다시 쓰거나 30일 뒤 자동 삭제로 번호가 풀려요.
  • 번호를 새로 받은 사람은 고객센터로 알리고, 운영자가 확인한 뒤 이전 계정의 번호만 풀어 줘요.
